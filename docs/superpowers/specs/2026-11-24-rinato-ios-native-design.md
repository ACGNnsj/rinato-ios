# 《圣灵家族 Rinato》nxnative 式 iOS 原生运行设计

日期：2026-11-24
状态：用户已于 2026-11-24 批准；本文不是实现完成声明

## 目标

把用户自己持有的 Switch《圣灵家族 Rinato》1.0.1 游戏包转换为可在其 iPhone/iPad 上侧载运行的原生 ARM64 应用，逐步达到标题显示、触屏操作、剧情推进、音视频与存档可用。

选择 nxnative 式路线的理由：保留原版 Unity IL2CPP 游戏逻辑，避免把整款游戏恢复并重写成 Unity iOS 工程。Switch 与目标设备同为 ARM64，工作集中在可执行文件加载、Horizon 服务替换和 NVN/Metal 适配。

这里的“nxnative 式”是技术路线，不表示第三方 nxnative 已支持本作，也不承诺一键转换。

## 前提与边界

- 首阶段只面向 **iPhone 11 Pro Max，iOS 27.2.1**，采用个人侧载与电脑辅助 JIT，不以 App Store 上架为目标。其他型号和系统版本不在首版兼容承诺内。
- 该设备是 A13/4GB RAM 级别，arm64e/PAC 与可执行内存行为、iOS 27.2.1 的 JIT 链路、实际应用内存上限都必须先用探针证明；不能把同为 ARM64 当成 ABI 和可运行性的充分条件。
- 原 NSO 从文件加载并执行会受 iOS 可执行内存与签名约束。若目标变成免 JIT、普通安装或上架，需要另评 AOT 静态重编译，不能视为本文方案的小改动。
- 只处理用户自己提供的游戏包和密钥；仓库、IPA、日志与文档不得捆绑 ROM、密钥或受版权保护的可再分发素材。
- 先复用本地提取/NSO 工具，并审计现有开源项目的许可证和可移植模块；不采用仍处 Early draft 的本地 SwitchRecomp 作为运行时基础。
- 不重制剧情、美术或 C# 工程，不先做全量 NVN/Horizon 兼容层；只按本作实际调用逐步扩展。

## 已确认事实

- 原包为 XCI/NSP，无游戏源码。1.0.0 与 1.0.1 ExeFS 已分别解密到工作区，数据块哈希已验证；RSA 签名未验证。
- 1.0.1 `main` 为 38,678,380 B，SHA-256 为 `31441da3f61393d80a31f837c04e920e35fb8c6b82ecdcfbd5a5c50ed20e1056`。
- `main` 是 Unity IL2CPP Switch 可执行文件，内存镜像约 `0x50fe000`，含 `global-metadata.dat`、Unity 资源文件名及大量 UnityEngine/NVN 字符串。
- 动态依赖包含 `multimedia.nss`、`Assets/UniNAS/Plugins/Switch/libunas.nrs`、`nnSdk.nss`、`nnrtld.nss`。哪些由包内提供、哪些必须由宿主实现，尚需完整盘点。
- 已解析 997 个动态符号、944 个未定义符号。这个数字用于说明不能盲目手工全补；实际需按启动调用轨迹确定最小集合。
- 当前只完成 ExeFS 侦察，尚未证明 RomFS 已完整提取、游戏能启动或任何 iOS 兼容性。

## 总体架构

1. **游戏包准备工具**
   - 复用本地 XCI/NSP 提取器，补齐 1.0.1 RomFS 与全部可执行模块的可复现提取。
   - 生成带哈希的清单，定位 IL2CPP 元数据、Unity assets、UniNAS 模块、音视频和 shader。
   - 输入路径只存在本地配置，不硬编码或上传密钥。
   - 首版只在电脑完成解密、提取和转换，再把数据包导入设备；不在 iOS 应用内处理原始 XCI/NSP 或密钥。

2. **iOS 宿主应用**
   - 原生 ARM64 进程，负责应用生命周期、文档目录、日志、触控/手柄、存档和 Metal 展示。
   - 首版采用侧载调试/JIT 路径，先证明签名与可执行内存模型，再接游戏代码。
   - 主要开发环境是 Windows。默认通过 macOS CI 编译未签名 IPA，再在 Windows 上侧载并辅助启用 JIT；游戏包、提取后的受版权保护数据和密钥不上传 CI。
   - 设置只保留必要的分辨率、输入和诊断项，不预设完整模拟器界面。

3. **NSO 加载与进程桥**
   - 按段加载包内实际存在的 NSO/NRO，处理 BSS、TLS、重定位、模块初始化和线程入口。
   - 显式处理 A13 arm64e/PAC 边界：原游戏代码、宿主函数指针和导入 trampoline 分别验证间接调用与返回，不混用未经证明的签名约定。
   - 未定义符号统一经过可记录的导入绑定层；每次未知调用记录模块、符号、参数和调用位置。
   - Horizon 的内存、线程、同步、时钟、文件系统与服务调用按真实轨迹实现。
   - 对未实现功能明确失败。不能为了让启动继续而静默返回成功，再把黑屏称为“兼容”。

4. **NVN → Metal**
   - 先建立 device/queue/window、资源池、texture 与 present 的最小闭环。
   - 再按标题和首个剧情场景的真实命令实现 command buffer、同步、buffer/texture 更新和绘制。
   - Switch shader 不能直接交给 Metal。优先复用许可证允许的解码/转换组件；若没有合适组件，只实现本作首屏所需子集并保留明确错误。
   - 每个图形里程碑保存实际帧截图和命令统计，不能用宿主自绘图片替代游戏画面。

5. **游戏服务与内容**
   - 文件访问只映射到导入后的只读游戏数据和应用可写目录；资源按需映射/读取，不把整个 XCI 或 RomFS 一次性载入 4GB 设备内存。
   - 触屏先覆盖确认、取消、方向、菜单、快进与对话推进；手柄使用 iOS 原生 GameController 能力。
   - 存档写入应用 Documents，采用临时文件加原子替换，保留一次旧档备份，并验证冷启动读档。
   - 音频、视频、UniNAS 与 `multimedia.nss` 分别取证和验收；跳过媒体或静音不能算完整通过。

## 分阶段验收与停止条件

### M0：执行环境与内容完整性

- 在 iPhone 11 Pro Max / iOS 27.2.1 跑通最小宿主、日志和 Metal 清屏，证明所选侧载/JIT 方式可执行测试代码。
- 分别验证 arm64/arm64e 切片、PAC 调用边界、JIT 可执行内存和实际可用内存上限；记录失败原文，不用桌面结果替代真机结论。
- 完成 RomFS/模块清单，确认 IL2CPP 元数据和首屏所需资源能读取，并给首屏设定实测内存预算。
- 若无法获得满足前提的目标设备/签名环境，暂停设备实现，只保留主机侧工具，不声称完成 iOS 移植；若 JIT 或内存模型不成立，先回到路线选择，不擅自扩大为 AOT 全量重编译。

### M1：原代码启动轨迹

- 加载 `main` 及真实依赖，完成重定位和初始化，进入有证据的 Unity/游戏代码路径。
- 产出按调用顺序排列的未知服务与符号清单，区分“必须实现”“可延后”“禁止假成功”。
- 若入口在基础运行时之外立即进入大量不可识别间接分发，先解决加载/重定位，不扩大 HLE 范围。

### M2：首个真实标题画面

- 游戏自身完成 NVN 初始化并提交命令，Metal 显示标题帧。
- 连续截取多帧，确认不是清屏、单帧偶然结果或宿主占位图。
- 记录 shader/纹理/同步缺口；若首屏 shader 转换路线不可行，停止扩展其他系统并重新选型。

### M3：可操作的最小闭环

- 触屏或手柄从标题进入第一段可交互剧情。
- 读取真实文本和素材，音视频分别记录状态；不能用跳过剧情掩盖资源或媒体问题。
- 建立存档并冷启动读回，比较关键进度与文件完整性。
- 这是首个可交付版本的验收终点。允许首版明确记录音视频缺口并在 M4 补齐，但不得把这些缺口隐藏为“完整移植”。

### M4：可玩性扩展

- 按剧情实际覆盖补齐菜单、养成/小游戏、视频、音频、存档边界与后台恢复。
- 完成一段连续实机流程后再扩大范围；性能优化只在真实瓶颈测量后进行。

## 验证原则

- 加载器、重定位、文件映射、存档等逻辑保留可在主机或设备重复运行的小型测试。
- 每个阶段提供设备日志、真实截图或存档往返证据；进程未崩溃不等于成功。
- 对原版的对照可使用用户能提供的 Switch 记录或可复现的 PC 模拟器基线，无法取得时明确标为未对照。
- 失败证据保留原始符号、地址与模块偏移，避免只记录“黑屏”“卡住”。

## 最终交付形态

- 可在约定目标设备上侧载的 IPA 与对应源码。
- 本地游戏导入/提取工具、哈希清单、构建说明和已知兼容项列表。
- 分阶段验证记录；未实现功能明确列出，不把“能到标题”包装成“全游戏完成”。

## 已锁定的首版条件

- 唯一验收设备：iPhone 11 Pro Max，iOS 27.2.1。
- Windows 主开发环境，接受电脑辅助 JIT；macOS CI 只构建不含游戏数据的未签名 IPA。
- 电脑提取后导入设备，首版验收到首段剧情可操作及冷启动读档。
- JIT、PAC 与 4GB 内存是首要技术风险，而不是已解决的兼容项。
